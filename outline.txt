10 Mins / section hands -on ?
Part A: Discovery is hard, and attackers know it
Declared vs shipped. Repackaging drift. The gaps are the attack surface.
Set the scene …
Declared vs resolved graph on a real project (mvn dependency:tree, npm ls --all, pipdeptree)
SBOM from manifest vs SBOM from binary artefact — Syft + CycloneDX plugins, side by side
Break the SBOM live: shade a jar, vendor source, rebuild a container. Components vanish
How code hides: renamed classes, payloads in resources, build-time injection
Dissect a real malicious package (from published research): manifest says one thing, binary does another
Snyk demo --?
Part B: Why green doesn't mean green
Three ways the data misleads: tool gaps, CVE process failures, EOL blind spot.
Same project, three scanners, different answers: Snyk (free tier), OSV-Scanner, Grype. Unpick why
Live CVE/NVD walkthrough: narrow version ranges, unscored backlog, ranges that stop at the support boundary - tomcat 8.5?
EOL blind spot: nobody files CVEs against dead branches. HeroDevs EOL DS scan (CLI or SBOM upload) to find them
Trace a fix in a supported release back through EOL versions the scanner says  green
endoflife.date for quick lifecycle lookups
Part C: The minimum that keeps you informed
Short and checklist-shaped: how to get to nothing in the ship list is a surprise.
Inventory the artefact, not just the manifest, every build
More than one scanner, plus a lifecycle check
More emphasis on keeping current
Judge before adopting: OpenSSF Scorecard, deps.dev, OSS Index  E
IDE plugins?
Decision path for findings: upgrade / patch in-house / accept / buy support
Take-home: one-page checklist with commands
Part D: The outside world has raised the bar
Machine-speed vulnerabilities, human-speed fixes. Plus regulators.
Vibe code etc condsequences on selected packages etc…
AI vuln discovery outpacing fixes,  EOL code as the undefended backlog
Demo: AI coding assistant grows the tree, picks poorly, hallucinates packages. Audit what it pulled in
Slopsquatting: attackers register the hallucinated names for real (sourced from published research)
CRA + US regulation: one slide each, primary sources only
Closing decision path names HeroDevs Never-Ending Support (NES) as the drop-in option
Part E - Wrap up
